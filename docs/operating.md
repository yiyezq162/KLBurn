# 现场怎么用

> 写给**拿着 U 盘站在服务器前面的人**。不需要懂里面怎么实现的。
>
> 做盘看 [`usb-rufus.md`](usb-rufus.md)，报告怎么读看 [`reports.md`](reports.md)，
> 第一次拿真机跑之前把 [`first-run-checklist.md`](first-run-checklist.md) 过一遍。

---

## 一句话

```
插盘 → 开机 → 选范围（60秒倒计时）→ 选时长（30秒倒计时）→ 走开
        两个菜单不按都用默认：全量测试 + 标准 30 分钟
                      ↓
   U 盘里多出一个文件夹：报告 + 全部原始数据 ← PASS / FAIL 大字
```

**所有等待的屏都有倒计时、都会自己往下走。** 这是硬约束：
插上盘没人管的时候它必须跑完，绝不能停在一个等按键的屏上。

> 屏幕上全是英文——Linux 文本控制台显示不了中文（会变一屏方块）。
> **U 盘里那份报告是全中文的**，不受影响。

---

## 一、完整流程

| # | 这一步 | 要不要人 |
|---|---|---|
| 1 | 插 U 盘，开机，BIOS 启动菜单选 U 盘（常见 `F11` / `F7` / `Esc` / `F12`） | ✋ |
| 2 | GRUB 菜单 5 秒后自动进入 | — |
| 3 | **显示报告存储位置**：绿色 `Data partition: ...` = 正常；黄色大框 = 没找到 U 盘数据分区，报告只会写到 `/tmp`、关机就没了 | 👀 |
| 4 | 尝试联网校时（接了网线才有动作，几秒到几十秒） | — |
| 5 | **选测试范围**（60 秒倒计时，默认全量） | ✋ 见 §二 |
| 6 | **选测试时长**（30 秒倒计时，默认标准 30 分钟）。选了"仅导出报告"时没有这一步 | ✋ |
| 7 | 自动采集硬件信息 | — |
| 8 | **配置核对面板**（60 秒倒计时，任意键继续） | 👀 见 §三 |
| 9 | **破坏性写入确认**（两道，默认跳过）。本轮范围不含硬盘压测时不问这一步 | ✋ 见 §四 |
| 10 | 性能基准 + 专项验证（机器空闲时测） | — |
| 11 | **压测**，屏幕是每 2 秒整屏重绘的仪表盘 | 👀 |
| 12 | 测后复查 → 出两份报告 → **PASS / FAIL 大字** + 逐项结果 | 👀 |
| 13 | 收尾菜单：`r` 重启 / `p` 关机 / `s` 进 shell / `t` 再测一遍 / `c` 清 BMC 事件日志 | ✋ |

## 二、第一个菜单：测什么

```
+==============================================================================+
|  SELECT TEST SCOPE                                                           |
+==============================================================================+
   [1]  FULL BURN-IN     everything below, run as one session  (default)
   [2]  CPU ONLY         CPU stress + computation validation
   [3]  MEMORY ONLY      memory stress + ECC re-check
   [4]  GPU ONLY         GPU stress + vendor diagnostics
   [5]  DISK ONLY        disk stress (still asks before writing)
   [6]  INVENTORY ONLY   collect + cross-check only, no burn-in at all

   Press 1-6 to choose, ENTER to accept.  Auto-select FULL BURN-IN in 34s
```

| 键 | 什么时候用 | 报告目录后缀 |
|---|---|---|
| **1 全量** | **出厂验收就用它。** 默认 | `_Full` |
| 2 CPU 单独 | 只想复验一颗换过的 CPU、或者怀疑算力/算错 | `_CPU` |
| 3 内存单独 | 换过内存条、或者查 ECC | `_MEM` |
| 4 显卡单独 | 只验显卡，不想陪跑一整轮 | `_GPU` |
| 5 硬盘单独 | 只压盘。**时长全给硬盘**（不是全量档的 30%） | `_DISK` |
| 6 仅导出报告 | 只想要一份配置清单，几分钟出结果 | `_INFO` |

**不管选哪个，硬件清单、配置核对、网卡三项都照跑**——它们合起来几十秒，
回答的是"这台机器装了什么、装得对不对"，那是任何一份报告的底座。

> ⚠️ **单项专测的报告不能当整机验收依据。**
> 报告抬头第一行就写着本轮范围，结论下面还有一句"哪些部件这一轮没测"，
> 目录名和报告文件名都带后缀。
> "仅导出报告"那一档**不会出现 PASS 大字**——屏幕上是中性的 `INFO`
> 加一句 "This is NOT a pass"。详见 [`reports.md`](reports.md)。

> ⚠️ **选了 `[4]` 或 `[5]`，而这台机器上没有那个部件时，流程会直接停下来。**
> 屏幕上打一块红色大框（`NO GPU FOUND` / `NO TESTABLE DISK`），
> 不再往下走，直接出报告并判 **FAIL**。
>
> 那个 FAIL 的意思是**「这一轮作废，多半是选错范围或测错机器」**，
> **不是**「这台机器坏了」—— 报告里会明写"这不是硬件故障"。
> 重新开机选 `[1]` 全量就行。
>
> CPU 和内存没有这个判断：没有这两样机器根本开不了机。

## 三、配置核对面板

采集完、压测开始前，先把"这台机器到底装了什么"摆出来让现场对一遍。
以前这些只有出报告才看得到——少一条内存、少一张网卡、少一块盘，
要等三十分钟压测跑完才发现，白等一轮。

```
  _  ___     ____
 | |/ / |   |  _ \ _   _ _ __ _ __
 | ' /| |   | |_) | | | | '__| '_ \
 | . \| |___|  _ <| |_| | |  | | | |
 |_|\_\_____|_| \_\\__,_|_|  |_| |_|
 Server Factory Burn-in Test   v1.9.5                       2026-08-10 20:07:39
+==============================================================================+
| SCOPE: FULL BURN-IN            CONFIGURATION REVIEW                          |
+==============================================================================+
|  SYSTEM                                                                      |
|    Manufacturer  Dell Inc.                  Product   PowerEdge R750         |
|    Serial        ABC1234                    BIOS      2.10.2 (2025-03-11)    |
+------------------------------------------------------------------------------+
|  CPU                                                                         |
|    2 x Intel Xeon Gold 6430  32C/64T        Total 128 logical CPUs           |
+------------------------------------------------------------------------------+
|  STORAGE                                                                     |
|    /dev/nvme0n1   1.6TB  SAMSUNG MZQL21T9HCJR   SN S6CVNE0T   [TESTABLE]     |
|    /dev/sda     446.6GB  DELLBOSS VD                          [MOUNTED]      |
+==============================================================================+
      Review the configuration above.  Press any key to continue.   [58s]
```

- **抬头左边写着本轮范围**，一眼看出这一轮打算干什么
- 60 秒倒计时，按任意键立即继续，超时自动继续
- 哪一项没有就整块不画（没显卡就没有 GPU 那块），不铺一屏 N/A
- `[TESTABLE]` 是**黄的**、`[MOUNTED]` / `[TEST MEDIA]` 是**绿的**——
  下一屏就是破坏性写确认，"哪几块盘会被擦掉"这一眼很值钱

这一屏的纯文本存档落在 `raw\config-review.txt`。

## 四、破坏性写入确认（默认跳过）

⚠️ **这是全项目唯一会毁掉数据的操作。**

```
+==============================================================================+
|  DISK STRESS TEST  (OPTIONAL, DESTRUCTIVE)                                   |
+==============================================================================+
 Disk inventory (model / capacity / serial / firmware / SMART health)
 has already been collected and will appear in the report either way.

 The optional STRESS test makes fio write RANDOM DATA directly to the
 RAW DEVICES listed below. ALL DATA ON THEM WOULD BE DESTROYED.
 Default is to SKIP. Only continue if you really mean to wipe these disks.

 DEVICE          SIZE   MODEL                SERIAL      PARTITION TABLE
 /dev/vda        2.0GB  -                    -           none (looks blank)

 Excluded (will NOT be touched):
   /dev/fd0      4.0KB  floppy drive
   /dev/sda      2.4GB  the KLBurn USB stick itself

 Type  yes  and press ENTER to continue to the final confirmation.
 ENTER alone, any other text (typo included), or 120s timeout  ->  SKIP.
```

- **两道确认**：先原样打 `yes` + 回车，再在最终警告屏上按一次 `y`
- 打错、直接回车、或者 120 秒不管 → **一律跳过**
- 启动 U 盘自己、有挂载分区的盘、软驱都会被**自动排除**，屏幕上列出排除原因
- **不确认也照样测硬盘**：型号 / 容量 / 序列号 / 固件 / SMART 健康状态早就采完了，
  顺序读带宽也照测（只读，一个字节都不写）

> **选了"硬盘单独测试"照样要过这两道。** 范围只是让这道确认必然被问到，
> 不是替你答应擦盘。

## 五、压测仪表盘

现场要盯的就是这一屏，每 2 秒整屏重绘：

```
 Server Factory Burn-in Test   v1.9.5                                     QUICK
+==============================================================================+
|                             BURN-IN  CPU + MEMORY                            |
+==============================================================================+
|  CPU     MODEL                              FREQ      TEMP    BUSY           |
|   #0     Intel Xeon Gold 6430              3100 MHz     67 C   100%          |
|   #1     Intel Xeon Gold 6430              3090 MHz     65 C    99%          |
+------------------------------------------------------------------------------+
|  MEMORY   Used   492 / 512 GB              ECC  CE 0 / UE 0                  |
|  NETWORK  4 ports, 2 up                                                      |
+==============================================================================+
|  ELAPSED 00:04:12   REMAINING 00:05:48                                       |
|  [########################............................]  42%                 |
+==============================================================================+
```

- 抬头中间是**这一轮在压什么**（单项专测时只有那一项），右边是档位
- 逐颗 CPU 一行、逐张显卡一行；CPU / 显卡 / 硬盘那几行**按判定用的那两条温度线
  上色**（绿 → 黄 → 红），读不到温度就不上色——读不到既不是"正常"也不是"异常"
- 框线全是 ASCII：现场多半是通过 BMC 的 KVM 或串口看的，
  Unicode 制表符有很大概率变成一屏乱码

硬盘单独压测时屏幕换成硬盘视角：逐盘的读写带宽、IOPS、温度。

## 六、跑完之后

屏幕上是 **PASS / FAIL 大字** + 二十几行逐项结果（FAIL 红、WARN 黄、SKIP 灰、PASS 绿），
下面写着报告在哪。

**报告在 U 盘的 `out\` 下**，一台机器一个文件夹。和文件夹同名的那个 `.html`
（和 `.pdf`）就是交给客户的，`raw\` 整个目录不外发。详见 [`reports.md`](reports.md)。

收尾菜单：

| 键 | 干什么 |
|---|---|
| `r` | 重启 |
| `p` | 关机（**报告已经落盘并 sync 过，可以直接断电**） |
| `s` | 进 shell 排查 |
| `t` | 再测一遍（同一台机器测两次不会覆盖，目录名会自动加序号） |
| `c` | **清 BMC 事件日志（SEL）** |

> **`c` 为什么单独一个键、还要打 `yes`**：机器拷完机之后 BMC 里常压着一堆装机
> 阶段的报错（拔插硬盘、电源没插好、反复上下电），跟出厂后的状态没关系，
> 留着只会让客户开机一看 SEL 全是红的。
>
> **只清事件日志，不动任何设置**——网络配置、用户、传感器阈值、启动项一概不碰。
> 另外要知道：IPMI 标准里能清的只有 SEL 这一个，有些厂商 BMC 另有独立的审计日志，
> 那些得进 BMC 网页界面清，这里够不着。
>
> 它**故意不进自动流程**：SEL 正是「BMC 事件日志复查」那一项的判定依据，
> 自动清就等于把自己的证据先销毁掉。所以要等报告出完再手动点。

按 `Alt+F2` 可以切到另一个控制台，root 免密登录，用来手工排查。

## 七、出问题了

### 启动阶段

| 现象 | 怎么办 |
|---|---|
| BIOS 里看不到 U 盘 | 见 [`usb-rufus.md`](usb-rufus.md) 常见问题 |
| 启动卡住看不到原因 | GRUB 菜单按 `e`，删掉 `quiet`，`F10` 启动 |
| 进了系统但没自动跑测试 | `Alt+F2` 登录后 `systemctl status klburn.service`、`journalctl -u klburn.service -b --no-pager` |

### 测试阶段

**报告写到了 `/tmp`** —— 数据分区没认出来。`Alt+F2` 后
`lsblk -o NAME,SIZE,FSTYPE,LABEL,MOUNTPOINT` 确认 U 盘第二分区是 exFAT、
卷标 `KLBURN`（大写）。

**硬盘测试一直被跳过** —— 看屏幕上列出的排除原因。最常见的是盘上有分区被
自动挂载了，这种情况脚本会主动避开，属于预期行为。

**报告里的时间不对** —— 开机后会先尝试联网校时，没接网线时只能退回 BIOS 的 RTC。
ISO 时区已设为 `Asia/Shanghai`；如果差了整 8 小时，说明这台机器的 RTC 存的是
本地时间，去 BIOS 里把时间改成 UTC 即可。

**阵列卡这项是 SKIP，只有型号没有固件版本** —— 这张盘里没带对得上的管理工具。
那类工具都是各家的闭源二进制，只能手工放进 `vendor/` 再重新出盘
（见 [`toolbox.md`](toolbox.md) 和 [`vendor/README.md`](../vendor/README.md)）。
**阵列卡始终只采集不压测，所以这一项永远不会是 FAIL。**

**某一项莫名其妙是 SKIP** —— 先看那条结论自己写的原因。两种完全不同的情况：
"这台机器没有这个部件"（客户有权知道，照常印在报告里）和"我们这张盘没带那个
程序"（不进交付报告，只在内部报告里）。见 [`toolbox.md`](toolbox.md)。
