# 报告文案规范（内部）

> **这份文档是给我们自己看的，不随报告交付。**
> 它规定的是：哪些东西可以出现在交付给客户的 `report.html` 里，哪些绝对不行。

---

## 一、先分清三样东西的归属

| 产物 | 去哪儿 | 能不能给客户看 |
|---|---|---|
| **ISO 测试盘** | 我们内部，发货前测试用 | ❌ 不交付 |
| **工程目录**（`raw/`、`meta.json`、`results.jsonl`、`klburn.log`、`sys_metrics.csv`…） | 我们内部留档，日后回档追溯用 | ❌ 不交付 |
| **`报告名.html`** | **随机器交付给客户** | ✅ **只有它** |

所以：

- **工程目录里怎么写都行**，越详细越好——命令原文、退出码、git hash、内部路径、调试信息，
  全都可以往里塞。日后客户反馈问题时，这些是唯一的证据来源。
  `collect_deep()` 就是专门干这个的，它只落数据、不产生任何判定。
- **`report.html` 里必须假设读者是客户的采购或运维**，他不知道也不需要知道
  KLBurn 是什么、盘是怎么做的、少了哪个工具、去哪儿补。

---

## 二、报告里绝对不能出现的东西

### 1. 我们内部的实现细节

| ❌ 不要写 | ✅ 改成 |
|---|---|
| 「本测试盘为精简版（未包含 NVIDIA 驱动）」 | 「本次测试环境未包含显卡驱动」 |
| 「盘内缺少 gpu_burn 工具」 | 「本次测试环境未包含显卡满载测试程序」 |
| 「盘内没有 storcli64」 | 「当前测试环境的管理工具不支持该型号」 |
| 「把 storcli64 放进构建目录的 vendor/ 后重新出盘」 | 整句删掉 |
| 「盘内缺少 DHCP 客户端」 | 「当前测试环境不具备该项检测条件」 |
| 「未发现任何本机硬盘（只有U盘）」 | 「本机未安装硬盘」 |
| 「源码版本：5fb41af-dirty」 | 整行删掉（留在 `meta.json` 里） |

判断标准很简单：**这句话里有没有只有我们才懂、或者只有我们才能去做的事？**
有就得改。客户看到「去 vendor/ 补个工具再重新出盘」，第一反应是"这机器是不是缺东西"。

### 2. 让客户误以为机器有问题的措辞

**能力缺失 ≠ 硬件故障。** 我们的工具没带某个厂商的管理程序，是**我们环境**的限制，
跟这台机器好不好毫无关系。这类情况：

- 状态一律判 **SKIP**，不判 WARN
  （WARN 会在报告抬头单独列一块，客户看到"告警"就会打电话问）
- 文案里必须明确写上一句 **「此项不影响整机结论」**
- 不要把原因归到硬件头上。写「当前测试环境未包含…」，
  不要写「阵列卡读不到固件版本」——后者听起来像卡有毛病

同理，**测试环境自身的问题绝不能判成硬件故障**。典型的是内存压测被 OOM killer
打死（退出码 137）：那是测试程序申请的容量超过了当时系统能给的，
和内存条好坏没有关系，必须判 WARN 并写明"不是内存故障"。

> 这条是有血的教训的。0.7.0 现场一台完全正常的机器，因为内存压测被 OOM 打死、
> 退出码 137 被当成"测试进程异常退出"判了 FAIL，硬生生被拦在出货前。
> **把好机器拦在出货前，比漏判更糟。**

### 3. 屏幕输出的英文

屏幕（Linux 文本控制台）显示不了中文，所以运行时输出一律英文；
但那些英文是给现场工程师看的，**不进报告**。
`result_add` 的 `detail` 字段是中文、只进报告，屏幕上只打 id 和状态。
这两套文案不要混用。

## 三、报告里应该有的东西

- 这台机器装了什么（型号、序列号、容量、固件版本），**有啥列啥，没有的标"未安装"**
- 每一项测了什么、结论是什么、依据的实测数据是什么
- 温度/功耗曲线，让客户看得见机器真的被压过
- 判定阈值（报告里显示的是本次**实际生效**的值，取自 `meta.json` 的 `thresholds`）
- 整机结论：**只看有没有 FAIL**，SKIP 和 WARN 都不拉低结论

---

## 四、这条规范是有测试守着的

不是靠人记。两处自动守卫，改坏了会跑红：

1. `tests/test-hw-checks.sh` —— 全局正则扫描 `result_add` 的 detail 和报告生成器里的
   中文串，命中 `测试盘|盘内|精简版|构建目录|重新出盘|vendor/|storcli|README|源码|commit|…`
   任何一个就失败。**新写的文案自动受它约束，不需要额外登记。**
2. `tests/test-report-render.sh` —— 真的生成一份 HTML 再去查，确认里面既没有
   git commit hash，也没有上面那批词。
   （在源码里 grep 会被注释里提到的变量名绊倒，所以查生成物。）

加新文案时，跑一遍：

```bash
./tests/test-hw-checks.sh && ./tests/test-report-render.sh
```

---

## 五、写文案的三个自查问题

1. 客户看完这句话，会不会以为**他买的机器**缺了什么/坏了什么？
2. 这句话里提到的东西，客户**有没有可能自己去做**？没有的话为什么要告诉他？
3. 这句话如果被截图发到群里问"这是什么意思"，我解释得清楚吗？
