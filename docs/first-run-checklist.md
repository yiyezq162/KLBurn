# 开工首台真机检查清单

> 这份是**内部**的，不随报告交付。
>
> 用途：拿到第一台真服务器时，照着它一条条过。等真机到手再现想要看什么，
> 一定会漏 —— 而机器通常只借得到半天。

离线能做的验证已经做到头了：[`tests/run-all.sh`](../tests/run-all.sh) 1245 项、
[`tests/mutate.sh`](../tests/mutate.sh) 87 条变异、
[`tests/e2e-qemu.sh`](../tests/e2e-qemu.sh) 把盘在 QEMU 里真开机跑完
（`--disk-stress` 还会真让 fio 写一次盘）、
[`tests/check-firmware.sh`](../tests/check-firmware.sh) 对账盘里的网卡固件。
**下面这些是 QEMU 结构上盖不到的**，只能上真机。

---

## 零、先看这条

**[`lib/collect.sh`](../rootfs/opt/klburn/lib/collect.sh) 里阵列卡后端物理盘那条路
（v1.2.0 的主功能）一次真机都没验过。** QEMU 里没有 MegaRAID，
单元测试喂的是构造出来的 sysfs 和 smartctl 输出。

它恰恰是最重要的一条：**这条路悄悄失效的表现是「报告写着 PASS，实际一块物理盘
都没查过」**，而带阵列卡的存储机又是最常见的机型。所以第一台能借到的
**带阵列卡的机器**，优先级高于一切。

---

## 一、QEMU 盖不到的，按优先级

| # | 项 | 为什么盖不到 | 看什么才算过 |
|---|---|---|---|
| 1 | **阵列卡后端物理盘 SMART** | 没有 MegaRAID 可模拟 | `raw/smart-pre/` 下要有 `sdX-pdN.txt`，且**内容是物理盘**（有型号/序列号/温度），不是空的逻辑盘。报告硬件清单里逐块列出来 |
| 2 | **压测前后 SMART 真的增长** | 虚拟盘不会长坏道 | 至少确认 `smart-pre` 和 `smart-post` 两边的键**逐项对齐**（同一批 key）。真增长可遇不可求，但对齐是必须的 |
| 3 | **IPMI / BMC** | QEMU 无 BMC | `collect_ipmi` 不再是 SKIP；`raw/ipmi-sdr.txt` 有读数；SEL 能读到 |
| 4 | **电源判定** | 要 BMC 的 Vin 交叉核对 | 双路都插电时 PASS；**故意拔掉一路**，应判 WARN 而不是 FAIL |
| 5 | **真显卡 + gpu_burn** | 无 GPU 直通 | `gpu_detect` PASS、`stress_gpu` 跑满、`gpu_metrics.csv` 有逐卡温度/功耗曲线 |
| 6 | **CPU 温度来源** | QEMU 无 coretemp | `sys_metrics.csv` 的 `cpu_temp_c` 非空；空了不算故障，但要知道这台机器的驱动是哪个 |
| 7 | **PCIe 链路降级** | 虚拟设备无 LnkCap/LnkSta | 有降级的机器上要**只报端点、不报桥**（§11-5） |
| 8 | **网卡协商速率** | 虚拟网卡无 ethtool 速率 | 万兆口跑满时 PASS；**故意插千兆线**应判 WARN |
| 9 | **非 Broadcom 阵列卡的管理工具** | `perccli64`/`ssacli`/`sas3ircu` 1.7.8 起已备进 `vendor/`，但**手上没有对应的卡**，测试里仍是桩（Broadcom 那条已在真卡上验过：型号/固件版本/逻辑盘都读到了） | 拿到 Dell / HPE / IT 模式的卡时，`raw/raid/` 下要有**真的输出**，不是一行报错。没对上的工具那一项必须是 SKIP，**绝不能是 FAIL** |
| 10 | **需要固件才能起来的网卡** | QEMU 里只有 virtio | 插 `bnx2x`（Broadcom 10G）或 `ice`（Intel E810）的机器上，`ip link` 要看得到物理口，`dmesg` 里不许有 `Direct firmware load ... failed`。1.5.0 之前这些卡在盘里根本起不来 |

### 1.7.0 新增的，一样只能上真机验

| # | 项 | 为什么盖不到 | 看什么才算过 |
|---|---|---|---|
| 11 | **`gpu_burn` 在真显卡上跑得起来** | 无 GPU 直通 | **这条优先级仅次于阵列卡。** 1.6.0 及以前的盘里 `gpu_burn` 只带了 sm_120 一代的 cubin（`nvprune --arch` 重复写不叠加），H200 / 4090 / A100 / 3060 上 cuBLAS 会找不到可用核、非零退出，然后被判成「显卡故障」。1.7.0 改成 `-gencode` 并补了 sm_75。**修法在构建期有自检，但"真卡上真能跑"一次都没验过** —— 第一张能借到的 N 卡上要看到 `stress_gpu` PASS、`gpu-burn.log` 里 `GPU N: OK` |
| 12 | **内存 ECC 计数（`verify_ecc`）** | QEMU 无 EDAC | 有 EDAC 的机器上 `raw/counters-pre.txt` 要有 `ECC` 行、且**标签是插槽名**（`CPU0_DIMM_A1` 这种，能对到主板丝印）。读不到就该是 SKIP，**绝不能是 FAIL** |
| 13 | **CPU 热节流计数（`verify_throttle`）** | QEMU 无 `thermal_throttle` | `counters-pre.txt` 有 `THROTTLE` 行。想主动验一次：把风扇调到最低跑 QUICK，应判 WARN 而不是 FAIL |
| 14 | **PCIe AER 计数（`verify_aer`）** | QEMU 不开 AER | `counters-pre.txt` 有 `AER` 行。固件没开 AER 的机器上该是 SKIP |
| 15 | **LLDP 邻居** | QEMU 无交换机 | 接了交换机的口上 `raw/deep/lldp-neighbors.txt` 要有对端设备名和端口号。**同时确认交换机侧看不到我们发的通告**（我们只用接收模式） |
| 16 | **`fwupdmgr` / `turbostat` / `sg_ses` / `mstflint` / NVMe 厂商插件** | 都要真硬件 | 各自的 `raw/deep/*.txt` 里是真输出而不是一行报错。**这几样都只留档、不参与判定**，读不到不影响任何结论 |
| 17 | **新界面在真 BMC KVM 上** | QEMU 的显示不等于 BMC 的 KVM | 配置核对面板和压测仪表盘的框线要是整齐的 ASCII，不能有乱码或错位；80 列的串口/KVM 下也不许折行 |
| 18 | **HWE 内核（如果启用了 `KLBURN_KERNEL=hwe`）** | 引导链和驱动集全变了 | 默认是 `generic`。要切之前，先在真机上确认：认得到所有硬盘和网卡、`nvidia-smi` 正常、BMC 和阵列卡照常。**这一项没在任何真机上跑过** |

### 1.7.5 ~ 1.8.4 新增的

**这一段整体优先级很高：1.8.3 和 1.8.4 两版全部是"离线改的、一次真机都没跑过"。**
两版动的又恰好是**报告上那些数字**和**电源判定**，而这两样在 QEMU 里
要么没有（无 BMC、无 RAPL），要么造不出真形状。

| # | 项 | 为什么盖不到 | 看什么才算过 |
|---|---|---|---|
| 23 | **CPU 封装功耗到底对不对**（1.8.3 修的翻倍 + 平均值）| QEMU 没有 RAPL，整条路是假 sysfs 测的 | 报告 2.2 那条功耗曲线要**同时**满足三样：① 峰值 ≤ `raw/deep/msr-pkg-power-limit.txt` 里 PL1 × 颗数（以前是它的两倍）；② 曲线**会抖**，不是一条直线（以前每个点都是"从开测到现在的平均值"）；③ 和 BMC 的 `Sys_Total_Power` 对得上量级。**顺手把 `raw/deep/powercap-tree.txt` 留下来** —— 1.8.3 事后想复核都复核不了，因为盘里从没留过这棵树 |
| 24 | **电源那张表**（1.8.3 的 `<BAD INDEX>` / 65535 W）| 要一台 BIOS 填错电源信息的机器（Supermicro X11DPG-QT 是已知的一台）| 客户报告的电源表里不许出现 `65535`、`<BAD INDEX>`、`Present, OK`；整行读不到时下面要有那句"这几项由主板 BIOS 提供，读不到不代表电源有问题"。**但空槽位仍然要被丢掉** —— 这两件事最容易一起改错 |
| 25 | **电源离散量（SDR）那条新判据**（1.8.3）| QEMU 无 BMC | 这是 1.8.3 唯一新增判定输入的地方。**故意拔掉一路电源线**：要判 WARN；**离散量说有电但模块报 Critical**：仍然只能 WARN，不许升成 FAIL（FAIL 只认数值传感器）。判错方向就是 §2-2 的反向误杀 |
| 26 | **显卡掉线检测**（1.8.0）| 要一张会掉的卡 | 已经在一台真机上抓到过（1.8.0 那份留档）。**再遇到掉卡的机器时确认**：`stress_gpu` 判 FAIL 且文案说明"温度/功耗峰值只反映掉线前"，不能再是 PASS 无警告 |
| 27 | **网卡「固件版本」那一格**（1.8.3）| 要一块 r8169 这类"给的是固件文件名"的卡 | 那一格应该是 `rtl8168d-2.fw`（没有目录）。**同时**在 I350/82599 那类机器上确认多段版本号（`1.63, 0x800009fb, 1.791.0`）原样留着 |
| 28 | **一台机器上把整份客户报告逐格读一遍**（1.8.4）| 这类问题断言结构上抓不到 | 1.8.3 和 1.8.4 加起来修了十几处"报告里印着一个我们没测到的数字/一个客户看不懂的词"，**每一处都是人拿着报告逐格看出来的，不是测试跑出来的**。所以真机跑完一定要**打开客户报告从头读到尾**，凡是读着别扭的格子都记下来。这一条比上面任何一条都值钱 |
| 29 | **工具名一个都没漏出去**（1.8.4）| 只有真机才会走到那些失败分支 | 客户报告里搜 `stressapptest`、`stress-ng`、`gpu_burn`、`nvidia-smi`、`dmidecode`、`ethtool`：**表格和正文里一个都不许有**（`<pre>` 里的原始日志是存证，不算）。失败分支的文案平时跑不到，正是最容易漏的地方 |

### 1.9.0 新增的（配置一致性核对 + 性能基准）

**这一版同样是离线改的，一次真机都没跑过**，而且新加的两块东西**在 QEMU 里
基本全是反面样本**：QEMU 里没有 BMC、没有 DMI 内存 PN、没有显卡、
四个基准程序一个都没有 —— 冒烟只验到"没有这些东西时干净地 SKIP"这一半。
**另一半（真的读到了、真的测出数）只能在真机上第一次见到。**

| # | 项 | 为什么盖不到 | 看什么才算过 |
|---|---|---|---|
| 30 | **一致性核对的"正常态"** | QEMU 里 DMI 内存明细、网卡固件、BMC FRU 全都没有 | 一台配置正常的机器上，`check_dimm_uniform` / `check_nic_uniform` / `check_disk_uniform` / `check_sn_consistency` 应当**全是 PASS**，而不是一片 SKIP 或一片 WARN。**一片 WARN 是这一版最可能的翻车方向**（占位符没过滤干净、分组键取错），一出现就先去看 `raw/dmidecode-memory.txt` 里那几格到底是什么 |
| 31 | **序列号一致性** | 要有 BMC | 正常机器上 BIOS 与 BMC 两处应当一致判 PASS。**顺手人工核对一次机身标签** —— 报告里写的就是"机身物理标签请人工核对"，那句话要站得住 |
| 32 | **平台关键设置读得对不对** | QEMU 的 x2APIC / VT-d / NUMA 拓扑都不是真的 | 报告 2.2 那三格要和 BIOS 里实际的设置**逐项对上**。对不上的话看 `raw/dmesg-pre.txt` 里 x2apic / DMAR 那几行原话 —— 判读函数只认内核的原话，认错了改判读函数，**别去改 BIOS 迁就报告** |
| 33 | **板载网口那一格** | 要一台 DMI type 41 填了东西的机器 | `raw/deep/dmidecode-onboard.txt` 有内容时，"共 N 个、其中 M 个可用"要和实际插的网线/BIOS 设置对得上。**很多主板压根不填 type 41**，那种情况显示"主板未上报板载网口信息"是对的，不是 bug |
| 34 | **显存 ECC 与行重映射** | 要数据中心卡（消费级卡这两项本来就 SKIP） | 有 A100/H100 这类卡时，两项应当是 PASS 而不是 SKIP。**`[N/A]` 绝不能被当成 0** —— 报告上出现"ECC 错误计数均为 0"而那张卡其实不支持 ECC，是这一版最危险的误报方向 |
| 35 | **显卡满载运行状态**（`check_gpu_load`） | 要真跑一轮 gpu_burn | 那一条的文案里应当有平均频率、平均功耗、风扇最高、距温度上限余量，而且**只报读数、不判达标**。**风扇那格在被动散热的数据中心卡上应当整个不出现**，不是"0%" |
| 35a | **显卡温度那两条线是卡自己报的**（1.9.3） | 有 N 卡的机器 | 报告 4.3 的图注应当是「告警线 X°C，判故障线 Y°C，两条线均取自显卡自身上报的限值」。X/Y 要和 `nvidia-smi -q -d TEMPERATURE` 里那张卡的降频 / 关机温度对得上（Ada 起是 T.Limit 余量写法，绝对值 = 当前温度 + T.Limit − 该项的 T.Limit 值）。**若图注里没有"取自显卡自身上报的限值"这句**，说明这张卡什么限值都没报出来、走的是 90/95 兜底 —— 记一笔，回来看是不是解析漏了一种写法 |
| 35b | **单卡机器也要有「显卡间互联带宽」这一项**（1.9.3） | 只装一张卡的机器 | 报告第三节里应当有一条 SKIP：「本机只安装了 1 张显卡，没有卡与卡之间的互联通道可测」。**整项不见了就是 bug** —— 看报告的人分不清是"不需要测"还是"漏测了" |
| 36 | **性能基准真的跑出数** | 显卡那两项手上没有卡，跑不了 | 四项都要有实测值。**拿到数之后先自己看一眼合不合理**（和厂商标称对个量级）—— 报告不判合格，数字对不对只能靠人判断，第一台尤其要看 |
| 36-2 | **内存带宽那一步不能把机器卡住** | QEMU 上已经踩过一次（缓冲区 5.8GB > 整机 4GB） | 看 `raw/bench/mem-bandwidth.log` 第一行的 `buffer size ... MiB/thread`：乘以「线程数 × 2」应当**明显小于**整机内存。大内存机器上顶到 512MiB/线程是正常的 |
| 37 | **硬盘顺序读带宽是只读的** | — | 这一项**不需要破坏性写入确认**就会跑。跑完确认：盘上原有数据完好、分区表还在。**这是这一版唯一一处新增的"默认就会碰硬盘"的行为**，虽然是只读，第一台真机上仍然要专门确认一次 |
| 38 | **性能基准阶段不会把流程拖住** | — | `PHASE 2/5` 那一段在什么都没放的盘上应当几十秒就过（只有硬盘读带宽）。屏幕上要能看到它在动，不能像卡死 |

### 1.9.2 新增的（让部件自己查一遍）

**这一版加的判定里，有四条的结论是"设备自己给的"**，而 QEMU 里没有 BMC、
没有真硬盘、没有真网卡 —— 离线只验到"读不到时干净地 SKIP"这一半。

| # | 项 | 为什么盖不到 | 看什么才算过 |
|---|---|---|---|
| 39 | **部件传感器复查**（`verify_bmc_sensors`） | QEMU 无 BMC | **这一条优先级很高，因为它是新加判定里唯一会大面积误报的那种。** 一台完全正常的机器上必须是 PASS，文案里报出"核对 N 项"，N 应当在 25~90 之间（十份真机数据的区间）。**一旦出现 WARN/FAIL，先别怀疑机器**：打开 `raw/ipmi-sensor-breach.txt` 看是哪一条、主板给的限是多少，再对着 BMC 网页里那个传感器核一遍 |
| 40 | **风扇位空着的机器**（同上） | 手上没有这种机器 | 拔掉一颗风扇（或找一台风扇位没插满的），确认判的是 **WARN 不是 FAIL**，而且文案里写着"既可能是该位置未安装部件，也可能是部件已停转"。判成 FAIL 就是把好机器拦在出货前 |
| 41 | **硬盘自检**（`verify_disk_selftest`） | 虚拟盘不做自检 | PHASE 1 发起、PHASE 5 读结果。正常机器上应当是 PASS。**跑 QUICK 档（10 分钟）时特别要看**：短自检约两分钟，跑不完会判 SKIP —— 那是我们的时间问题，不许判 FAIL。顺手确认 `raw/smart-selftest/` 下每块盘都有一份 |
| 42 | **网卡自检**（`check_nic_selftest`） | virtio 不实现 `ethtool -t` | **不插网线也要能跑**（这正是它的价值）。Intel/Broadcom 卡上应当 PASS；国产卡驱动多半不实现，判 SKIP 是对的。**确认它没有把链路踢掉**：它排在拉链路之前，跑完之后 DHCP 那一步照常能拿到地址 |
| 42a | **有口没插网线时，网卡自检仍然要 PASS**（1.9.3） | 一台机器上留一个口不插线 | 这是 1.9.2 现场那台 6530 的原样场景。`ethtool -t` 对没插线的口总结论必然是 FAIL（五个子项里只有 Link test 是 1），**但整项必须判 PASS**，文案里要点名那个口、说明「链路子项查的是网线与对端设备，现场未接网线时必然不通过」。**判成 FAIL 就是把一台好机器拦在出货前**（二号红线）。对照 `raw/nic/<口名>-selftest.txt` 逐子项看一眼 |
| 43 | **固件自检不许出现在客户报告里**（`collect_fwts`） | — | 打开交付报告搜「固件自检」「ACPI」，**一个字都不该有**；内部报告里必须有。真机上 fwts 大概率会报出若干条告警，那正是不能给客户看的原因 |
| 44 | **校验清单** | — | 报告目录下应当有 `SHA256SUMS`，行数 = 目录里的文件数（不含它自己）。当场 `sha256sum -c SHA256SUMS` 跑一遍，必须全 OK |
| 45 | **memtest86+ 启动项** | QEMU 里验过菜单，没验过真 BMC KVM | 开机菜单里应当有第二项；**但默认第一项仍然是我们的测试，5 秒后自动进**。选进 memtest 跑一小段确认它真能起来（跑完手动重启，它不落任何结果文件，报告里也不会有） |
| 46 | **专项验证两条**（`validate_cpu_sdc` / `validate_gpu_diag`） | 1.9.5 起 CPU 那条**盘里真的带了程序**（OpenDCDiag），这条路第一次上真机 | 先看 CPU 那条：正常机器上应当是 **PASS**，文案写「全核运行 120 秒的计算正确性诊断，未发现计算结果错误」。**万一它判 FAIL，先别信** —— 打开 `raw/validate/cpu-sdc.log` 找到具体是哪一项失败、复跑一次确认能重现，再去怀疑 CPU。跑不起来（参数/驱动不匹配/被超时打断）时判的必须是 **SKIP 而不是 FAIL**（离线已验退出码 64 那两条路）。GPU 那条盘里没带程序，应当是不进交付报告的 SKIP |
| 46a | **CPU 浮点算力换了程序**（1.9.5） | 手上没有 Intel 服务器可以新旧对比 | 报告第三节「CPU 浮点算力」必须有实测值 —— **非 Intel（海光 / AMD）机器上这一项以前永远测不出来，这一版就是为它改的**。`raw/bench/cpu-linpack.log` 里应当有 `Best GFlops` 那一行和一列 `MaxResidual`（残差应当在 1e-12 量级）。⚠️ **Intel 机器上这个数会比 1.9.4 低一到两成**，那是换了测量方法，不是机器变慢了 —— 拿新旧报告对比之前先看 CHANGELOG 1.9.5 第三节 |
| 46b | **测试范围菜单**（1.9.5） | QEMU 里验过按键和目录后缀，没验过真 BMC KVM | 开机第一个菜单是「SELECT TEST SCOPE」，六个选项、60 秒倒计时。**先什么都不按**，确认它自己回落到全量、报告目录以 `_Full` 结尾。再挑一台跑 `[6] INVENTORY ONLY`：应当**跳过时长菜单**、几分钟就出报告，屏幕上是青色 `INFO` 大字加一句 "This is NOT a pass"，**绝不能是绿色 PASS**；报告抬头写着「本轮范围 仅导出硬件信息」、目录以 `_INFO` 结尾 |
| 46c | **硬盘专测那道确认**（1.9.5） | — | 选 `[5] DISK ONLY` 时**必须照样弹出那两道破坏性写确认**。范围只是让它必然被问到，不是替操作员答应擦盘。不确认的话应当只测读带宽，盘上原有数据完好 |
| 47 | **压测频率那两个数** | QEMU 没有真频率 | 报告里「平均频率」和「最低频率」**最低那个不许比平均那个高**（1.9.2 修的，r08 那份真机报告上印过）。顺手看一眼 GPU 那条结论里的「平均频率 X（最低 Y）」也是同一个方向 |

## 二、破坏性写盘：QEMU 里过了，真机上还得再过一次

1.5.0 起 QEMU 里能真跑这条了：

```bash
sudo ./tests/e2e-qemu.sh --stage full --disk-stress
```

它会真让 fio 往两块虚拟盘上写满，然后验三件事：空白盘确实被写了、
**开跑前预埋在「U 盘」里的上一轮报告一个字节没变**、`stress_disk` 判 PASS。

**但 QEMU 里的 U 盘是一块 usb-storage 虚拟设备**，真机上是一根插在 xHCI 上的
真 U 盘，中间隔着完全不同的枚举路径。所以真机还得再过一次：

找一台**盘里没有任何要留的数据**的机器，专门跑一次：

1. 硬盘压测确认那一步，如实打 `yes` 回车
2. 最终警告面板列出的盘 —— **逐块核对**，尤其确认**启动 U 盘不在里面**
3. 按 `y` 开始
4. 跑完拔盘，插 Windows 电脑：**U 盘里的历史报告必须还在，分区必须还能读**

> 这一步是整个项目最危险的一条路径（[§8.2](architecture.md#82-裸盘写入的排除规则storagesh)）。
> **Ventoy 盘尤其要单独过一次**：排除有三层，而 Ventoy 场景下前两层
> （`rm=1` / 有分区挂载）**同时**落空，只剩 `live_media_disks` 那一层。

## 三、引导方式

QEMU 里 **BIOS 和 UEFI 两条都验过了**（`--firmware bios|uefi`），
所以真机上主要是补环境相关的：

- [ ] BIOS 启动菜单里能不能看到这根盘（有些机器要关 Secure Boot）
- [ ] **Ventoy 方案**（见 [`usb-rufus.md`](usb-rufus.md) 末尾）——
      走的是四层回退里的**第 0 层**（dm 设备），和 Rufus 完全不同的路径。
      QEMU 里没法真装 Ventoy，只能真机验
- [ ] 报告落盘位置那一行是**绿色**的（`Data partition: /dev/sdb2 -> ...`）。
      黄色大框 = 没认出数据分区，报告只在 /tmp，关机就没了

> 「U 盘上没有可用 exFAT 分区」这个场景 QEMU 里验过了
> （`--no-data-partition`）：报告不会被写到不认识的分区上，流程也不卡死。

## 五、发现问题时

**先分清是"能力缺失"还是"硬件故障"。** 判 FAIL 之前问一句：
这台机器真的坏了，还是我们的盘缺个工具 / 驱动太旧 / 现场没接线？

后者一律 SKIP，文案写「此项不影响整机结论」。
**把好机器拦在出货前，比漏判更糟** —— 见
[`report-policy.md`](report-policy.md) 和 [§2](architecture.md#二四条核心原则)。

真发现判定 bug：

1. 把 `raw/` 整个目录留下来（那是唯一的证据）
2. 把触发它的原始日志做成 fixture 加进 `tests/`
3. 修完在 [`tests/mutate.sh`](../tests/mutate.sh) 里加一条变异，确认新守卫真的会红
4. bump 版本 + 写 [`CHANGELOG.md`](../CHANGELOG.md)
