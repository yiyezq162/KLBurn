# 内存专用盘（KLBurn-MEM）

> 一批内存有问题，要一台一台过、把坏的那几条按序列号点出来。
> 整机老化盘干这件事太重了：要选范围、要选时长、要采一堆和内存无关的东西。
> 所以从同一份源码出第二种盘 —— **插上、开机、走开三分钟、拔盘**。

```
插盘 → 开机 → （什么都不用选）→ 约 3 分钟 → 拔盘
                      ↓
   U 盘里多出一个文件夹：日期_时间_容量_CPU_MEMSP
   例：20260812_171151_32GB_2x-INTEL-XEON-GOLD-6530_MEMSP
   ├── ….html            ← 交付：逐条内存的 SN / 型号 / 频率 + 结论
   ├── ….pdf
   ├── ….csv             ← 工程文件：一条内存一行，多台机器可拼总表
   └── raw\               ← 内部留档
```

> **目录名是纯 ASCII 的**（1.10.1 起）。1.10.0 那版带中文前缀「内存测试_」，
> 但这个串要同时活在三个地方：现场那块 Linux 文本控制台（没有中文字体，
> 整段显示成方块）、exFAT 目录名、以及 SHA256SUMS 和批次汇总工具的输入。
> `MEMSP` 后缀一样一眼认得出是内存专用盘出的报告，而且哪儿都不会出问题。
> 注意顺序和整机盘**不一样**：这边容量排在 CPU 前面。

---

## 它测什么、不测什么

| | |
|---|---|
| ✅ **逐条内存的明细** | 槽位 / 容量 / 厂商 / 型号(PN) / **序列号** / 类型 / 运行频率 / 标称频率 |
| ✅ **内存容量核对** | 装机容量 vs 系统识别容量（少一条内存立刻看出来） |
| ✅ **内存条一致性** | 厂商 / 颗粒型号 / 运行频率混插 → WARN |
| ✅ **序列号核对（查假条子）** | **序列号重复 → FAIL**；读不出序列号 → FAIL（可降成 WARN） |
| ✅ **芯片出厂记录比对** | 读 SPD 原片；两条内存的记录**逐字节相同 → FAIL**（整片克隆） |
| ✅ **追溯字段** | 生产日期（年/周）、Rank、ECC 位宽、颗粒厂商、厂商专属追溯区 |
| ✅ **内存压力测试** | 默认 150 秒，覆盖系统可用内存的绝大部分，逐字节写入并回读校验 |
| ✅ **ECC 计数复查** | 压测**前后**逐条 DIMM 的可纠正/不可纠正错误差值 |
| ✅ **内核日志** | 只看内存那一族（EDAC / 坏页 / 说明是内存的 MCE） |
| 🟡 **平台信息** | 整机型号、主板型号、BIOS 版本、CPU 型号与路数、内存总量 —— **只为说明这份清单来自哪台机器，不做任何判定** |
| 🟡 **网卡** | **只用来联网校时**，型号/速率/连通性一个字都不进报告，不产生任何判定 |
| ❌ 硬盘 / 阵列卡 / 显卡 / 电源 / BMC / PCIe | **完全不碰。** 被测平台上这些可能压根没有 |
| ❌ 性能基准 | 一项都不跑 |
| ❌ 任何菜单 | 不选范围、不选时长、不问擦盘确认 |

**这张盘一个字节都不往硬盘上写。**

## 判定口径：只有内存坏才 FAIL

这是这张盘最要紧的一条，和整机盘不一样：

> **网卡坏了、阵列卡坏了、PCIe 在报错 —— 都不影响这份报告的结论。
> 只要内存本身能正常读写、ECC 计数没涨，就是 PASS。**

具体落在两处：

1. **不产生任何非内存判定。** 主流程根本不调用 `collect_nic` / `collect_raid` /
   `gpu_detect` / `check_psu` 这些，所以报告里不会出现它们的结论行。
   `tests/test-mem-edition.sh` 里有逐个函数名的断言钉着。
2. **内核日志只认内存那一族。** `mem_dmesg_pattern()` 收的是
   `EDAC MC<n>: <n> CE/UE`、`Memory failure: 0x…`、`Corrupted low memory`、
   以及明确说了是内存的 MCE。
   **`uncorrectable` / `Uncorrected` / 裸的 `Hardware Error` / `Machine Check`
   一个都不收** —— 那几个词 PCIe AER 和 GHES 也在用，收了就会把一张坏阵列卡
   算到内存头上。这一组有成对断言：EDAC 内存错误必须命中，
   阵列卡/PCIe/硬盘/网卡/显卡的报错必须**不**命中。

### 例外：序列号重复也判 FAIL

上面那条"只有内存坏才 FAIL"有一个例外，而且是**这张盘最先要抓的那件事**：

> **两条正品内存不可能有相同的序列号。**

序列号写在**内存条自己的存储芯片（SPD）**里，由厂商唯一分配 —— DMI type 17
的 `Serial Number` 是主板从 SPD 读出来的，不是主板自己编的。所以同一台机器上
两条内存的序列号撞在一起，概率不是"小"，是**不存在**：只可能是 SPD 被人改写过，
也就是翻新或假冒。

这一条**不用等压测就能判死**，而且**没有开关**。现场那批假条子里有好几组
序列号完全一样，压测还都能跑过 —— 光靠压测抓不住它们。

报告里这几行会**整行标红**，序列号那一格挂一个「与其它内存条重复」的红标签，
表格前面还有一段说明为什么这就是假的。

**读不出序列号**默认也判 FAIL（正品 SPD 里有这一格，读不到属于异常）。
这一支留了开关，万一以后遇到确实存在的空 SPD 正品（很老的模组、某些 OEM
定制条），在 `klburn.conf` 里加一行就退回 WARN：

```sh
MEM_SN_MISSING_IS_FAIL=0
```

> ⚠️ 空槽位不参与比对。多个空槽的序列号占位符都是 `NO DIMM`，
> 一起比会得到一堆假重复。判据复用 `_serial_is_bogus`，有断言钉着。

### 关于那串"很长的序列号"

现场 2026-08-12 问：报告里的序列号只有 `175B36BA` 八位，而内存条标签上印的是
`HOPA00030844522378` 这样十几位的长号，能不能读到长的？

**那八位不是被截断的，它就是完整的。** JEDEC 规定 DDR4 的模组序列号字段
**只有 4 个字节**（SPD 偏移 325~328），按十六进制打出来就是 8 个字符。
标签上那串长号是厂商自己的**生产追溯号**，印在标签和二维码上，
不在标准序列号字段里。

长号如果有电子记录，只可能在 SPD 的**厂商专属数据区**（DDR4 是偏移 353~381，
共 29 字节，JEDEC 不管里面放什么）。所以 1.10.0 起这张盘会**直接读 SPD 原片**：

- 读到了 → 报告的「内存条芯片中的出厂记录」一节里会有「厂商追溯记录」一列
- 那片是空的 → 那一列显示 —（说明这家厂商没往里写，不是我们读不到）
- 整个平台读不到 SPD → 这一节整块不出现，`check_spd_clone` 判 **SKIP**

同时多拿到几样 dmidecode 给不了的：**生产地点、颗粒厂商、SPD 里的生产年/周**。

> ⚠️ **只读，绝不写。** 往 SPD 写一个字节就能把一条好内存变成砖。
> 也**绝不做 `i2cdetect` 盲扫** —— 服务器的 SMBus 上还挂着 BMC、风扇控制器、
> 背板，盲扫能把机器扫挂。只读内核驱动（`ee1004` / `at24` / `spd5118`）
> 已经建好的 eeprom 节点，也就是内核自己认定"这是一片 SPD"的那些。
>
> ⚠️ **读不到是常态。** 很多服务器平台的 SMBus 归 BMC 管、或者被 BIOS 锁了，
> 主机侧根本读不到；DDR5 的 `spd5118` 驱动要内核 6.10，而这张盘是 6.8。
> 一律判 SKIP，**绝不是 FAIL** —— 那是平台的事，跟这条内存好不好无关。

顺带白捡的一条更硬的证据：**两条内存的 SPD 逐字节完全相同 = 整片被克隆**。
比序列号重复还硬 —— 序列号还只是一格，整片相同连生产日期、追溯区都一样。

### 序列号有 8 位和 18 位两种，都是正常的

同一批内存插在两台机器上，序列号长度可能不一样：

```
1BA3172A              ← 8 位（Jintide C5218R、Xeon 6133、海光）
80AD01233537A7DDDD    ← 18 位（EPYC 7542、Xeon Gold 6530）
```

**和 DDR4/DDR5 无关** —— EPYC 7542 是 DDR4，报的就是 18 位。是 BIOS 抄了
多少字节的差别：SPD 里模组序列号那一格 JEDEC 只给 4 字节，但 JEDEC 同时定义了
一个 9 字节的「模组唯一标识」：

```
厂商 ID(2) + 生产地点(1) + 生产日期(2, BCD) + 序列号(4)
80 AD        01            23 35              37 A7 DD DD
   ↓            ↓             ↓                    ↓
SK Hynix      地点 1      2023 年第 35 周      模组序号
```

18 位那种**信息更全**。报告会把它拆成一张小表，并写明两种长度都正常
（不写的话现场会以为哪台的 BIOS 坏了）。

> 拿 7542 那台实测对过，三处自洽：`80AD` 和同一块里的
> `Module Manufacturer ID: Bank 1, Hex 0xAD` 一致，`2335` 和
> `Asset Tag ... (date:23/35)` 一致。

### 生产日期：查拼凑条子的硬线索

`dmidecode` 把模组生产日期藏在 Asset Tag 后面的括号里
（`P1-DIMMA1_AssetTag (date:22/51)` = 2022 年第 51 周），1.9.9 之前从来没渲染过。
现在它是明细表的一列。

用法很直接：**同一批买来的正品，生产周次会挨得很近**。现场那台 Jintide C5218R
的 8 条三星内存实测是 2022-W50 / W51 / W52，很典型；而拼凑翻新的条子日期会
散得到处都是，甚至出现晚于购入时间的日期。

四态语义和整机盘完全一致：

| | 什么时候 |
|---|---|
| **PASS** | 序列号齐全且不重复、压测无校验错误、ECC 无新增、内核日志干净 |
| **FAIL** | **序列号重复（假条子）** / 压出了数据校验错误 / 新增不可纠正 ECC / 内核报了内存错误 |
| **WARN** | 混插（配置问题，不是坏）；压测被 OOM 收掉（测试环境限制，不是内存故障） |
| **SKIP** | 这台机器/这个内核给不了这项数据（例如没有 EDAC 驱动） |

「BIOS 没填序列号」是 **`—`，不是故障** —— 报告里专门有一句话说明这点。

## 报告长什么样

**抬头**：公司名 + `内存专用测试报告`。

**结论大字下面紧跟一句蓝框**，这一句是红线，不许挪走、不许删：

> **本报告仅针对内存。** 本轮对本机安装的每一条内存做了信息登记与压力测试，
> 并核对了压测前后的内存错误计数。**本机的处理器、硬盘、网卡、显卡等其它部件
> 本轮均未测试，本报告不能作为整机验收依据。**

理由和单项专测那条红线一样：一个孤零零的绿色 PASS，读报告的人会当成整机验收
通过。**把"没测"包装成"通过"，比不做这个功能还糟。**

四节，就这么多：

1. **平台信息** —— 六格，说明这份清单来自哪台机器
2. **内存明细** —— 主表，序列号和型号用等宽字体（拿来逐字核对的）；
   序列号重复的行整行标红
3. **压力测试** —— 做没做、做了什么项目、覆盖多少容量、计划/实际多久、
   起止时间、校验错误数、ECC 新增数。**没压过的那一轮这里会明说没压过**，
   并写清楚这份报告因此不能用来判好坏
4. **测试结果** —— 逐条判定

> 压测那一节的数字全部来自压测函数自己记的 `metrics`，报告这边一个都不硬编码。
> 用的是哪个程序**故意不渲染**（工具名不进交付报告），数字照常给。

## 工程文件（CSV）

`<目录名>.csv`，**一条内存一行**，主板那几列在每行重复：

```
整机型号,主板厂商,主板型号,主板序列号,槽位,容量,厂商,型号,序列号,类型,配置频率,最高频率
```

这样多台机器的 CSV **首尾相接就能拼成一张总表**，在 Excel 里按序列号或型号
一排序，有问题的那批立刻聚到一起 —— 这正是"买了一批坏内存"要的东西。

UTF-8 **带 BOM**（不带的话 Excel 双击打开中文表头是乱码）。
型号里带逗号（`M321R4GA3BB6-CQK, 32GB` 很常见）会被正确引起来。

## 出盘

```bash
sudo ./build/build-iso.sh --edition mem
```

产物 `out/KLBurn-MEM-<版本>-<日期>.iso`，和整机盘的文件名区分得开。
写盘方式、exFAT 数据分区和整机盘完全一样，见 [`usb-rufus.md`](usb-rufus.md)。

想改压测时长（默认 150 秒）：

```bash
KLBURN_MEM_BURN_SECONDS=600 sudo -E ./build/build-iso.sh --edition mem
```

> ⚠️ **两三分钟压不出"这条内存能长期稳定工作"，它压的是"现在有没有明显坏"。**
> 要筛一批可疑内存就把时长加大再出一张盘；报告里会如实写出本次压了多久，
> 不会拿两分钟的结果去冒充老化测试。
>
> 想做更彻底的覆盖（地址线 / 位模式、以及操作系统占掉的那部分内存），
> 盘里的 GRUB 菜单有 memtest86+ 那一项 —— 它裸机跑、不落结果文件、
> 进不了报告，属于"操作员另选的第二种跑法"。

## 两种盘的差别只在三处

同一份源码、同一套 lib、同一套判定语义。构建时钉死的差别只有：

| | 整机盘 | 内存盘 |
|---|---|---|
| 开机拉起 | `factory-test.sh` | `memtest.sh` |
| 报告标题 | 服务器出厂老化测试报告 | 内存专用测试报告 |
| ISO 文件名 | `KLBurn-*.iso` | `KLBurn-MEM-*.iso` |

第一处由 `chroot-setup.sh` 改 `klburn.service` 的 `ExecStart` 实现，
**改完当场核对** —— `sed` 没匹配上是静默的，做出来会是一张"文件名写着 MEM、
开机却跑整机全测流程"的盘，而构建日志里一个字的异常都没有。

## 现场屏幕

全英文（Linux 文本控制台显示不了中文）。**没有仪表盘**，压测期间就是每 10 秒
追加一行：

```
  [MEM] 00:01:20 / 00:02:30   used 88412/98304 MB   ECC CE=0 UE=0
```

故意不用整机盘那块整屏重绘的仪表盘：那块面板要读逐颗 CPU 频率/温度、网口、
显卡状态 —— 等于把这张盘刚砍掉的东西又拉回来一遍，而且整屏重绘要求把别的
写入源全部掐干净。为一段两分半的压测背这一整套约束不划算。

报告目录名带中文前缀，屏幕上打的是**滤掉非 ASCII 之后**那一段
（日期/容量/CPU 都在，足以对上是哪一次）；U 盘插到 Windows 上看到的是完整的
中文目录名。要纯 ASCII 目录名就改 `klburn.conf` 里的 `MEM_DIR_PREFIX`。

收尾菜单里 `[t] test again` 排在最前面 —— 这张盘的典型用法是一台接一台地插过去。
