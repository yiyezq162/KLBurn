# 许可证与第三方分发边界

仓库根目录的 MIT 许可证只覆盖 KLBurn 自有原创代码与文档。
Ubuntu 系统、Linux 内核、固件、字体、运行库和第三方工具保留各自许可证与归属，
不能把整张 ISO 宣称为 MIT。

## 当前审查事实

本次公开前审查仍未完成，尚不能据此宣布现有 ISO 已满足公开再分发条件。
历史内部构建通过、哈希一致或工具可运行，均不构成分发权利证明。

| 组件类别 | 当前证据与限制 |
|---|---|
| Ubuntu、Linux、GNU 工具、memtest86+ 等 | 存在 GPL/LGPL 等组件；需按具体包版本保留许可证，并落实适用的对应源码提供方式。核对范围包括包的 Source、Built-Using／Static-Built-Using，以及独立于根文件系统的启动程序。仅链接上游首页不是完整源码交付证明。 |
| 固件与 CPU 微码 | 许可随具体固件包而异，不能由内核 GPL 推断全部固件适用 GPL。 |
| UEFI 启动链 shim | 实际 EFI 文件已与 Ubuntu 的 `shim-signed 1.58+15.8-0ubuntu1` 对账，其 Built-Using 指向 `shim 15.8-0ubuntu1`。完整源码版权声明还包含 OpenSSL／SSLeay 等条款，不能仅按签名包的简短 BSD 声明处理。当前源码保留[完整原文](licenses/shim-15.8.COPYRIGHT)及相应致谢；旧私有 ISO 尚未补入这份完整声明，不据此宣称可公开分发。 |
| OpenBLAS、字体、zlib、zstd | 保留对应许可证、版权及适用的再分发说明。静态或动态链接方式须按实际产物核对。 |
| NVIDIA 驱动和 CUDA 运行库 | 已从哈希核对一致的 595.84 安装包提取 Driver License Agreement（2025-02-25）。第 1.1(d) 条有条件允许用于开源内核的分发，要求不修改二进制并向接收者提供协议；另有硬件与用途限制。实际 ISO 条件符合性及 CUDA 运行库条款尚未全部核清，不能把 open 内核模块许可套用于全部组件。 |
| gpu-burn、cuda-samples、OpenDCDiag | 已取得 cuda-samples 固定源码版本的 BSD-3 文本，及 OpenDCDiag 固定版本的 Apache-2.0 与附带 MIT/BSD-3 声明；必须保留全部适用归属。当前私有候选的 gpu-burn 来源记录为 `0d19c94dcb2e9b6858b7586a4c327674cd67113b`，保留 BSD-2 原文及实际 CUDA 工具链 EULA；来源记录不替代静态链接组件的分发审查，也不能证明其他旧二进制的来源。 |
| Intel LINPACK、MLC | 免费下载不等于无条件再分发；`redist.txt` 也不能替代其所引用的完整许可协议。 |
| Broadcom StorCLI 及其他厂商管理工具 | 须获得适用版本的分发依据；不能因为内部测试盘已有二进制就直接向公众发布。 |

### 已安装包的版权路径

1.11.5 实际 ISO 的只读清点中，full 的 885 个已安装包有 871 个、mem 的 676 个
有 662 个在标准 `/usr/share/doc/<包名>/copyright` 路径可读；两版相同的 14 个包
存在缺路径或断链，需要复核。部分原文已在选定启动声明中保留，但不能据此
宣布全部包的版权和归属已经覆盖。

1.11.6 构建入口在全部装包和清理操作之后、打包之前运行 `package-notices.py`。
它使用[基础包版权索引](licenses/base-packages/base-packages.json)中与固定源 ISO
及精确二进制版本对应的原文，恢复已确认的标准路径缺口，包括源镜像遗留的
OpenSSL 断链；不恢复安装器程序。已有可读声明不覆盖，缺少适用精确版本时停止。
随后逐包检查全部已安装 dpkg 包，结果留在盘内
`/usr/share/doc/klburn/licenses/base-packages/presence.json`。
这是源码中的构建规则；实际 ISO 的覆盖分母以该候选的独立盘内审查为准。

1.11.6 私有候选（构建提交 `55b3c49`）已独立读取最终双版 ISO，full 885/885、
mem 676/676 个已安装包的标准版权路径非空可读，逐包哈希与构建收据一致。
实际 Source/Built-Using 及保留启动组件版本所需的 570 个源码版本组合均在现有
私有源码索引中；本次对账未重新验证全部归档字节或 DSC 签名。
上述结果不能解除厂商组件分发权、全部嵌入代码归属或对应源码实际交付的发布闸门。

索引原文来自锁定 Ubuntu 源 ISO 的 squashfs 层。OpenSSH 的服务端与 SFTP 包
使用同一精确版本客户端的共享版权文本；OpenSSL 使用同一精确版本 libssl3t64
的共享文本，直接恢复其标准路径，不依赖已经失效的 libssl3 链接。
路径解析限定在目标根文件系统，允许文档目录与 common-licenses 内的合法链接，
不能让绝对链接落到构建宿主机。此检查只证明所查包的版权文本存在且可读，
不证明所有手工安装组件、嵌入代码、许可条件或对应源码义务已完成。

## 发布边界

1.11.1 的源码编译助手将许可原文和附带声明复制到离线组件目录；
成对发布入口同时要求这些文件进入哈希清单。gpu-burn 许可入盘位置为
`/opt/klburn/tools/licenses/gpu_burn/`，基准工具许可随各自目录保留。
这项检查只证明指定文件被保留，不证明厂商 EULA、静态链接组件许可、
对应源码提供义务或全部分发条件已经满足；旧二进制不能凭补一份当前上游
许可证就冒充来源已经核实。许可内容必须与实际版本对应。
两版 ISO 的 `/usr/share/doc/klburn/` 保留 KLBurn 自有代码的 MIT 原文和本说明；
该位置的 MIT 不覆盖其他工具、驱动、固件或整个系统。
GPU 工具编译助手还要求实际 CUDA 工具链根目录中的 `EULA.txt`，并将原文与
静态链接的程序一同保留。其来源版本必须匹配编译工具链；不能拿另一版本的
网页、驱动协议或 BSD 许可证替代 CUDA 协议。保留协议仍不等于所有分发条件已满足。

- 不删除第三方版权声明、许可证或必要归属。
- 不把客户原始报告、私有测试样本、凭据或内部构建日志作为公共 Release 附件。
- 新版公开下载元数据只包含版本、tag、源码 commit、日期、文件名、大小、SHA256
  与公开资产 URL；内部 manifest 与失败记录保留在私有验收资料中。
- 历史 tag、历史源码与历史二进制也属于仓库可见性变更的审查范围。
- 尚未解决的具体许可或敏感资料问题不能通过勾选“检查通过”来消除。
